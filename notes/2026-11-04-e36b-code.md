# 任务 E36b 实现（luna-max）：候选条件的未来记忆（noisy-candidate memory）单因素训练实验

先完整阅读 notes/2026-11-04-e36-design.md（尤其 §1、§3、§9 与 §5），再读 tools/e33_model.py、tools/e33_train.py、tools/e33_eval.py、runs/e36_20261104/ 下的 protocol/analyze 脚本（复用其评测与哈希协议）。

## 实验
- 基座：runs/e33_20261104/B/run/ep80.pt 与 B_s2/run/ep80.pt（各自做 C/T 两个单元，共4个）。
- C（对照）= 原 hold memory 续训；T（处理）= 训练与推理都用"当步带噪候选"的 future 记忆：训练时采 noise/t，x_t=(1-t)·noise+t·a_demo，策略记忆改为 F(z,q,x_t.detach())（x_t 是归一化动作；转绝对命令=q+x_t·std+mean 后重算 FK，与 E33.futures 同口径）；JEPA/rec/mask/IDM 仍用 a_demo，各损失权重、flow 梯度回传规则、学习率、batch、噪声与 t 的配对不变。推理新增采样函数：每个 Euler 步用当前 x 重新算 future/memory 再调用 flow.velocity（10 步，10 次 predictor；报告新增时延）。
- 冻结 encoder 与 EMA target（保持 ep80 的 target 补法与 E36 一致），更新 predictor/flow/memory/prop 及原辅助头；54 维统计不变；只用 2812 train 窗口；eval 266 窗只做锁定的最终评估，不挑 checkpoint（固定最后一个）。
- 预算：每单元≤0.45 GPU 小时，计时/评测另≤0.1，总≤1.9，硬截止 2。先做≤20 步计时，据此为所有单元定相同的 step 上限（超时则减步并标 underpowered）。不得续跑正式 80 epoch。

## 评估输出（复用 E36 的评测口径）
动作：全 chunk 关节 RMSE、官方 EEF step8/16/32、手关节，266 窗 episode 配对 bootstrap；hold/oracle/shuffle 未来记忆的响应（同 E36 §3 的表，对 C 与 T 各一份）；K8/K16 多样性与 best-of-K 上界；G_action 简版（同起点换 demo/hold/跨 episode 动作，输出差异与相对 JEPA 目标误差）；推理时延 p50/p95。
