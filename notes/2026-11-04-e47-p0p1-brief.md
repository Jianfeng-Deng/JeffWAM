# 任务 E47：端到端 JEPA-WAM 的 P0–P1 设计合同（天机；sol high；只设计，不写训练代码）

## 用户目标（原话要点）
端到端 JEPA 式世界动作模型（WAM）输出机器人控制指令；训练中显式加入关键图像区域的像素解码；世界模型学到的动作信息必须在端到端流程里被使用：原始当前观测 → 编码 → 由潜变量生成候选动作块 → 预测并评估每个候选的后果（未来潜变量）→ 选最优候选并执行 k 步；由"当前潜变量+候选动作"得到的未来潜变量必须能解码出未来帧的关键物体。每个动作一个 token，避免对动作取平均。前 1–8 步误差优先，但保留长时域规划能力。URDF/FK 空间信息必须留在输入里。天机与 Piper 是两个独立任务，各自训练、不共享权重（Piper 由另一个 agent 做，所以请把模型代码做成配置驱动：动作维度、相机、时域、chunk 长度、FK 特征函数均为配置项）。

## 本任务范围：P0 + P1，仅天机
- **P0 数据与评测接口**：时域用秒/原始帧定义（15 Hz，+4/+8/+16/+32 原始帧 = 0.27/0.53/1.07/2.13 s）；按完整 episode 切分沿用 80 fit / 4 dev / 9 eval（eval={7,18,38,56,64,66,77,88,90}，index 见 data/e32_windows_20261103/index.json，stride 8，266 eval 窗）；输入包含顶视图、measured q、因果 dq、命令序列、FK/URDF 特征（用 E46 采用参数 runs/e46_recalib_20261104/params_adopted.json 与 tools/e46_project.py，掌点 2D ROI 先验；E46 结论：掌点可用、指尖未验收、高度不可用——不得依赖指尖像素或高度）、slot mask（瓶并集/左手/右手/箱）。要写清与 E33 数据路径（tools/e32_data.py）的复用/替换，保证能复现 E33-B 数字（B ep80 在 266 窗对 hold 的误差）。闭环评测协议留接口占位（MuJoCo proxy/真机由用户决定，本阶段不实现）。
- **P1 世界模型**：(1) 编码器 E：DINOv2-B 后 4 块可训，全 token 网格 24×40（不再池化到 12×20，E33_sub 显示池化破坏物体细节），说明显存/时间可行性与 token 维度（256 共享潜变量？是否每 token 维度提升）；(2) 预测器 F：每个动作一个 token（动作 + 该步 FK 手几何，E33 的 4 步均值池化必须去掉），因果时间 Transformer，对当前 z_t 做 cross-attention，输出 +4/+8/+16/+32 的未来 token；多步 rollout 损失（链式喂预测）；EMA 目标（B 配方：0.996→1 + VICReg 方差 0.01，C/SIGReg 已证明更差）；(3) 关键物体解码器 D：24×40 token → 手/瓶/箱 mask 与关键区域像素 L1（物体权重 1.0/背景 0.05 沿用，权重图 object_pixel_weights），同时作用于真实未来潜变量和预测未来潜变量，预测的未来必须可解码；(4) 逐步逆动力学损失；(5) 动作头：P1 先保留 E33 的 flow-matching 单样本头（读 z_t，不读 hold-future，E36 证明 hold-future 无新信息），以便做 P1 门槛对照；候选多样化与评分留给 P2/P3。损失权重建议表（JEPA/rec/mask/IDM/flow/rollout），flow 梯度占比过大（E36：编码器末块 72%）时的平衡办法（如 stop-grad 或梯度占比自适应，需单因素可检验）。前 8 步误差优先的损失加权方案（flow 与 predictor 都要）。
- **P1 通过门槛（需预注册、给出统计方法）**：(a) 动作互换：同起点真实动作 vs shuffled/hold，预测未来潜变量对在线目标的 LN-L2/cosine 胜率≥90%（episode bootstrap 下界>0.5）；(b) 预测的 +16/+32 mask IoU 在手/瓶/箱上相对 copy 的改善（E33-B：仅右手优于 copy，瓶 .44 vs .67、箱 .76 vs .89、左手 +16 .42 vs .48）；(c) 关键区域像素误差/PSNR 相对 copy 与 E33-B（20.35/19.94 dB，物体 MSE 0.0205）；(d) 动作误差：1–8 步与全 32 步相对 hold 的百分比不劣于 E33-B（B：step32 左/右 +32/+26%，step1 左 +6%）；(e) 多步 rollout（+4→+8→+16→+32 链式）误差界。每项给出 pass/fail 阈值与失败后退路。
- 已知教训必须融入：训练时间比任何辅助损失更重要（E32/E33 均如此）→训练预算要充足并等算力对比；单一路径成功示教导致动作-后果混淆（Tianji 只有 93 条）→P1 门槛只做"动作敏感性"的诊断，不得宣称反事实正确；predictor 动作条件目前只在辅助损失里起作用（E36）；E34 显示动作确实携带瓶子运动信息（moving 样本不足）。
- 资源：H20-191 共享卡（只用空闲卡，显存空闲≥16GiB 且利用率≤10%，不碰他人进程）；P1 正式训练预算建议≤8 GPU 小时（给出分解：烟测/计时/主训练/评测），每实验配对种子至少 2；磁盘新增≤20 GB。
