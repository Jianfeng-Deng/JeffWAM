# E36：动作条件世界模型失配诊断与候选选择设计
- 日期：2026-11-04；已完成代码核对、B/B_s2 ep80 的轻量评测和设计；未启动任何训练。
- 结论：用户对“世界模型未参与动作评估/选择”的指责成立；“完全只是行为拟合、世界模型没学到动作信息”则过强。JEPA/重建/掩码确实训练动作条件预测，但现有策略把 hold 预测当作确定性状态扩展。
- 本文与 E36b 均为独立离线研究，不替换 `AGENTS.md` 指定的现役规划器/MuJoCo outcome model，不恢复已终止的 E33_sub。

## 1. 代码证据与“失配”的准确含义
- `tools/e33_model.py:E33.infer`：当前顶视 RGB→z；`futures(z,q,-mean/std)` 生成 hold 的 +16/+32；拼入 `flow_memory`；32×54 高斯噪声经10步 Euler，只采单样本，不预测该样本的后果、不评分。
- `losses`：JEPA/rec/mask 的 future 使用真实 `act`；flow 的 `pf` 另算 hold。`flow` 对编码器与 predictor 没有 stop-grad。
- 因而原 B **训练与推理的策略记忆均为 hold，没有通常的输入分布 train–test mismatch**；失配是“训练了动作条件预测，却用无动作选择的方式调用它”，以及把真实动作 future 接到策略头时的条件支持失配。
- `flow_memory` 在 D 中只移除 future tokens；D 仍有 predictor 与 JEPA/rec/mask/IDM 辅助训练。B–D 比较只检验额外 hold tokens，不检验是否需要世界模型辅助损失。
- 保存梯度末次抽样 step14050：flow 梯度占各损失梯度范数之和，编码器末块 B/B_s2=72.2%/72.2%，predictor=68.2%/65.0%。这是单次范数比例，不能当作梯度方向/全训练因果贡献；证据见 `audit.json`。

## 2. 实测协议与完整性
- 只读加载 `runs/e33_20261104/{B,B_s2}/run/ep80.pt`，不跟随 latest；校验哈希在各 `*_runtime.json`；源代码与索引哈希在 `protocol.json`。
- 固定官方266个留出窗口、9个episode={7,18,38,56,64,66,77,88,90}；只用顶视 RGB、当前实测 q，54维顺序 A7+B7+L20+R20，绝对命令与弧度。

## 4. 多样性、覆盖上界与B–D解释
- 同窗候选离散度用全chunk各坐标无偏标准差的RMS：B K8/K16=.04679/.04671rad，B_s2=.04507/.04506；K16均方成对距离的平方根=.06605/.06373rad。
- K16“每个样本误差再平均”=.11539/.11329；“先平均动作再算误差”=.10607/.10434。这两种mean不同；平均动作不是原候选之一，也不保证接触/轨迹可行。
- best8相对单样本RMSE改善15.4% [12.1,19.0]/14.6% [12.1,17.3]；best16=19.0% [15.5,22.8]/17.7% [15.1,20.5]；best16比mean16仍低11.3% [8.7,14.7]/10.1% [8.3,12.4]。
- 固定随机选16=.11467/.11338rad，与单样本接近；best16比单样本至少好10%的窗口比例（episode等权）=70.3%/68.3%，best16优于物理hold命令比例=86.1%/86.8%。这是示教动作覆盖上界，不是任务成功率。
- best按全chunk关节RMSE选，不能再按左右EEF分别重选；mean16的step32 EEF反而比该best更小，说明不同选择目标不能互换。
- 历史官方step32：B=55.64/72.33mm，B_s2=55.14/74.26，D=59.31/76.63；D仅比B差3.67/4.30mm，比B_s2差4.17/2.37mm。不同噪声下本次数字略异，不冒充历史复现。
- 没有D第二训练种子，也未加载D重跑配对差异；原summary只有各自CI，不能靠CI重叠计算配对显著性。当前证据只支持“future-token增益小且跨种子不稳”，不宣称D=B。
- 原因：hold future由相同z/q确定，条件上不新增信息，只提供计算深度/偏置；D保留当前视觉、q和全部辅助损失；flow可走当前视觉捷径。梯度竞争/未来token被忽略是待证假说，不能用B–D差距直接证明。

## 5. 五条结论与修改边界
1. **需改架构目标/训练验证**：动作生成目前仍主要是示教条件分布拟合；世界预测作为辅助任务与hold特征存在，尚无“评估候选后果再选择”的闭环。
2. **只需推理改即可试验**：保留hold生成，增加K8/16、候选真实动作FK预测与无训练评分；先报告oracle覆盖上界，再检验评分能否兑现，不能直接部署oracle记忆替换。
3. **若要候选future反馈策略，必须改训练**：本次oracle替换显著恶化；仅在推理时自迭代“先生成→future→再生成”会进入未见条件，不能当作免费的修复。
4. **推理防护/测量可先做**：FK有限性与动作范围检查、失败回退、固定随机种子、记录时延和拒绝率；无需训练。绝不把预测关节当下一次实测q。
5. **训练损失调整另作因果实验**：flow梯度占比较大，stop-grad/增JEPA权重有动机但未证实；先保持单因素对照，不把更多权重或更低重建误差当成排序能力。

## 6. 候选动作生成与评分接口（设计，未实现为部署路径）
```python
encode_current(top_rgb, q54, causal_dq54, dq_valid) -> Context  # z[1,240,256]
generate_candidates(ctx, stats, seeds, K=8, noise_scale=1.) -> Commands[K,32,54]
validate_commands(commands, measured_q, limits, calibration) -> Valid[K], Reasons
forecast_candidates(ctx, commands, stats) -> Futures[K,2,240,256], Masks[K,2,4,12,20]
predict_e34(ctx, commands, current_instance_state) -> State[K,3,6,9], Valid  # h=5/10/20
score_candidates(ctx, commands, futures, masks, goal, state=None) -> Scores[K], Components
select_candidate(commands, scores, valid, fallback) -> Command[32,54], Audit
```
- 第一版K8=8个噪声种子×同一hold记忆；K16只扩噪声种子。可加hold命令作为额外基线但不偷偷计入K；随机/单样本/评分选必须使用同一候选库。
- 温度先固定noise_scale=1；.5/1可作预先固定的消融，但改变初始噪声不等于有校准的后验温度。不同子目标/CFG当前无条件输入、无dropout训练，不能直接启用；需要新训练，且不重启E33_sub。
- 每候选按`(command-q-mean)/std`归一化，用现有`E33.futures`和`e28_hand_geometry`重算完整绝对命令FK；严禁沿用示教FK、未来实测q或别的候选缓存。
- +16/+32分别使用前16/32步命令；现predictor每4步均池化，4步组内顺序不可辨，是动作时序门槛的结构限制。mask_head输出左右手/瓶并集/箱，不能当作六实例预测。
- `validate`先检查finite/关节限位/步间变化与投影有效性，再预测；无效候选不评分，保持原K分母并记拒绝原因；全无效回退当前measured_q的hold。范围和速度阈值从机器人配置/fit统计固定，不从eval挑。
- 不调用decoder也可评估latent/mask；仅对选中候选解码可视化。每次重规划重新读取q，短前缀执行长度单独验证，不进行本轮真机执行。

| 前景latent目标距离：+16/+32的LN-L2+cosine，对当前目标区域加权 | 能，已有encoder/predictor | 目标来自用户指定或fit参考顶视图/区域，禁止该eval窗未来帧；时相/背景偏差须校准 |

| E34质心/bbox到目标箱区域的距离/进入边界余量 | 能复用现有R0 AC，无需再训 | mask-assisted当前实例输入，h=5/10/20而非16/32；不得捏造32头；不能把projected_in_bin称放置成功 |
| IDM循环误差：idm(pool(z),pool(f16))与mean(a_norm[:16])之差 | 能，ep80保留IDM | 只预测前16步均值54D，不支持全轨迹/32步反推；自洽可能是共同偏差，不是外部动力学证据 |
| B/B_s2预测方差、E34三种子方差、微扰稳定性 | 能复用检查点，但增时延 | 两成员不是校准置信区间；E33 predictor确定且dropout0，不能直接声称MC-dropout不确定度；校准器/新ensemble需训练 |
- 先按fit/dev固定各分量尺度与权重，`S=w_goal*d_goal+w_geom*d_geom+w_idm*d_idm+w_unc*u`，不在266 eval上调权；E34和离散分数默认关闭，待其门槛通过再加。

- E24/E25排序未过70/80%门槛；E28审计证明已存value走legacy E24桥而非原生E28/FK，原生门未测。禁止把这些历史分数当成可用reranker保证。

## 8. 候选选择的预注册通过标准与失败条件
- 下轮冻结K={8,16}、目标定义、评分权重/阈值、2个基座、种子列表；分别报告：单样本、固定随机选、动作均值、无真值WM评分选、真实误差best-of-K上界。所有方法候选与有效性筛选一致。
- 主目标为全chunk关节RMSE；WM评分选相对单样本和随机选均改善≥10%，配对episode-bootstrap 10000次95%下界>0，两个基座各自满足；相对mean16改善≥5%且CI下界>0，证明超出简单平均。
- EEF位置/旋转/手分别报告，左右step32不得恶化>5%；同时报告可靠moving瓶的几何目标代理，禁止用“更像示教”替代任务成功；真实成功只能由独立有效评估给出。
- oracle best16的已测上界约18–19%，是覆盖预算；WM实现后需同时报告兑现比例 `(single-WM)/(single-oracle)`，分母非正则记不可用，不做无界收益宣称。
- 以episode为重采样单位、同一draw配对；模型种子分别报告，不扩充独立样本数。266窗已用于本次诊断，后续同窗结果是开发验证；严格确认需另行冻结的新episode，不能事后称本结果“预注册通过”。
- 失败：G_action/样本量不达标；WM选不优于随机或mean；优势只来自静态/单臂/单种子；靠未来标签/失效候选剔除获益；偏爱不动或预测不可见；NaN不回退；K8端到端p95>120ms则暂停在线接入并继续离线分析。失败不启动训练或放宽门槛。

## 9. E36b最小训练实验（仅方案，≤2 GPU小时，未执行）
- 不推荐仅把`pf=F(a_demo)`喂flow：会泄漏标签，且推理没有a_demo；本次oracle恶化说明必须对齐可得条件。
- 最小单因素方案：在新的隔离实现中改`losses`，先采noise/t与`x_t=(1-t)*noise+t*a_demo`，策略记忆改为`F(z,q,x_t.detach())`；原JEPA/rec/mask仍用a_demo，原loss权重和flow梯度回传规则先保持一致。
- 配套改`E33.infer`/一个新的采样函数：起始x=noise，每个Euler步用当前x重新算future/memory，再调用现有`flow.velocity(x,t,mem)`；训练与推理都使用当步带噪候选。不能继续用固定hold memory，也不能把x当实测q。
- 对照C：原hold memory；处理T：上述noisy-candidate memory。都从同一个B ep80初始化、完整冻结encoder与EMA target，更新相同predictor/flow/memory/prop及原辅助头；配对batch/noise/t、同学习率/步数，保持54D统计不变。
- 在B/B_s2初始化各做C/T共4个短续训单元；每单元≤.45 GPU小时，预留≤.1 GPU小时计时/评测，总≤1.9 GPU小时，硬截止≤2。先≤20步计时定所有单元相同step上限，超时则减步并标underpowered，不改单元预算或续跑正式80epoch。
- 仅2812 train窗口优化；eval266只作锁定最终评估，不挑checkpoint。保存独立E36b目录、逐损失梯度、实际GPU时间、相同K候选诊断与新增10次predictor带来的推理时延。
- 判定同时看动作误差、G_action与可部署WM排序，不能仅看flow loss；stop-grad future到flow或提高JEPA权重留作后续单因素，避免本次同时改三件事。即使T改善也不自动证明具备候选选择能力。
