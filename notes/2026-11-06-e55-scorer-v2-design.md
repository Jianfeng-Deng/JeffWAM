# E55 评分器 v2 设计（Claude，2026-11-06）

## 为什么重做
- E48–E53：B1 评分头（“事件是否在窗口内发生”二分类，演示窗口训练）在 8 个评估集上 G_rank≈0.47–0.52、G_semantic 不过，AUC≈“下一事件类型”先验。原因：只有演示动作的窗口、没有反事实后果标签，学到的是阶段检测器，不是动作价值。
- E54：E33-B 预测器对动作敏感（演示预测比 hold 更接近真实未来 99%+，比 shuffled 94–98%）；免训练的“最近示教目标距离”评分 demo>hold 0.77–0.81、demo>shuffled 0.73–0.80（非正式口径）。信号在表示里，缺的是正确的打分目标。

## 设计原则
1. 打分 = 预测未来与“目标”的距离（V-JEPA 2-AC / DINO-WM 一类），不训练事件分类头。
2. 明确范围：Tianji 只有成功示教，没有失败数据，所以 v2 度量的是“动作后果有多像示教/朝目标推进”，不能声称选出比示教更好的动作；“优于示教”需要带结局的 rollout 数据（Piper 有 136 条推理录制和 DAgger，留给 Piper 分支）。
3. 选型在 fit 集上按 episode 交叉验证做，评估集只报告一次；预先登记主变体。
4. 评估必须排除“有运动 vs 无运动”这个混杂：新增与示教运动幅值匹配的对照候选（shuffled 已部分满足）和 hold 以外的运动型负例。

## 打分形式
S(a) = - d( phi(ẑ_h(a)), g_k ) - lambda_risk * risk(a)；第二阶段可选 + lambda_v * ( V(ẑ_h(a)) - V(z_t) )。
- phi：手 ROI + 目标瓶 mask 池化的 token（物体中心），对照全局池化 token。
- g_k（目标）三选一，按复杂度递增：
  G-A 最近邻示教未来：在 fit 窗口里按当前表示取 K 近邻，目标 = 它们真实未来 token 均值（E54 已验证雏形）；
  G-B 事件原型目标：以 E49 事件帧附近的真实 token 为按事件/手侧的原型，目标 = 当前因果事件 k 的原型（用 E49 的 330 个事件，不做二分类）；
  G-C 任务终态目标：瓶入箱的终态 token，用于长地平线。
- d：相对 L2 / 余弦；可选轻量度量学习（自监督：同一进度相位的真实未来互为正例），不用事件标签。
- V（可选，第二阶段）：对轨迹内所有帧回归归一化进度或到下一事件的时间（稠密标签，类似 VIP/LIV），分数用增量；按 episode 交叉验证选正则与步数，不看评估集。

## 验证与门槛（沿用 gates.py，补充项用括号标出）
- G_rank：demo>hold、demo>shuffled、demo>reverse，episode 等权，10,000 次 bootstrap，平局边界 0.02，NaN 留分母；评估集 8 集（7,18,38,56,64,66,77,88）。（补充：demo>幅值匹配的运动对照。）
- G_action：不依赖解码器的版本——预测未来到真实未来的距离排序（E54 预言机）+ 目标距离排序；FK 重算与限位沿用。
- G_invariance：背景替换与 ±16 px 平移后分数排序不变（需重新编码，GPU 或 CPU 小样本）。
- 时延：K=11 候选的评分部分，仅报告。
- G_semantic 对距离评分不再适用；改为“分数与事件进度的单调关系”（Spearman，按轨迹），仅报告。

## 修订 1（同日，针对 OOD 的质疑）
问题：纯“像不像示教”的距离在 OOD 处没法判断——候选或当前状态偏离示教时，分数只会说“不像”，不会说“好”或“不可信”。这是 G-A（最近邻示教目标）的固有局限，G-A 降级为先验/支持度量，不再作主分数。
E55 前置检查（eval 266 窗口，全局池化 token）：当前状态到 fit 示教库的最近邻距离与演示候选的预测误差只有弱相关（Spearman 0.12–0.14，近/中/远三分位的误差中位数 0.393/0.390/0.403，几乎持平），说明“离示教库远”本身不是可靠的不确定性信号；评估集 9 集到 fit 的最近邻距离都在 0.09–0.18，没有自然的 OOD episode，OOD 行为只能靠合成 OOD 候选和实机 rollout 检验。候选类型的预测未来到最近 fit 真实未来的距离：demo 0.153 < shuffled 0.162–0.168 < reverse 0.190 < hold 0.195，jitter 5/10% 与 demo 几乎相同，20% 才明显更远。
修订后的结构：把“好不好”和“可不可信”分开。
1. 进度项（好不好）：目标是任务/事件目标（G-B 事件原型、G-C 任务终态）而非“示教相似度”，d(ẑ_h(a), g_k) 越小越好，对新颖动作也成立，前提是预测器在该处可靠。
2. 可靠性项（可不可信）：认知不确定性，候选来源：(a) 预测器集成分歧——E33 已有 B、B_s2（同配置不同种子）、C、D 检查点，可用 B vs B_s2 的预测分歧；(b) 微扰一致性——对动作加小扰动，预测未来应平滑变化（jitter 候选已有）；(c) 支持度量（最近邻距离，当前仅作辅助，因相关性弱）。
3. 悲观与弃权：S(a)=进度−lambda·不确定性；当某候选不确定性超阈值则记为“不可判”；若所有候选都不可判，回退到策略自身的采样，不让评分器强行选择。弃权率作为一等指标报告。
4. 新门槛 G_ood：(i) 不确定性对“示教候选 vs 合成 OOD 候选（20% 微扰、幅值放大 2x/3x、逆序、跨阶段 shuffled）”的 AUROC；(ii) 在评估集上，评分器覆盖率（未弃权比例）与已判部分的 G_rank 同时报告；(iii) 各集 OOD 候选被弃权或降分的比例。
5. 无法在现有数据验证的部分，写明：“优于示教”和“真实 OOD 上的判断”需要实机 rollout（策略 E 加评分器 vs 不加评分器的闭环对照）或 Piper 的带结局 rollout，现有 Tianji 数据只能证明评分器在示教分布内和合成 OOD 上的行为。

## 修订 2（同日，针对“OOD 但可能成功的路径会被拒绝”）
结论：悲观 + 弃权在结构上会压制 OOD 路径，这是离线数据下无法消除的取舍（没有 OOD 结局标签，就无法区分“OOD 且好”与“OOD 且坏”）。设计上不假装能解决，而是把它做成可调、可验证、可扩展：
1. lambda 与弃权阈值是旋钮，不是常数：S=进度−lambda·不确定性；lambda 小则允许高进度的 OOD 候选通过。报告“OOD 程度 × 评分器接受率”的曲线，而不是单点。
2. 两种模式：部署模式（悲观：不确定性高则降分/弃权，回退到策略采样）；探索模式（乐观地选“高预测进度、中高不确定性”的候选，作为受控试验，用于扩大支持集），探索只在实机有保护措施时开启。
3. 进度项基于任务目标，OOD 候选只要预测器可靠、预测进度高就能得高分；是否可靠由集成分歧/微扰一致性判断，而不是由“像不像示教”判断。
4. 结局数据闭环：每次受控试验记录（状态、候选、预测进度、不确定性、真实结局），用于（a）校准不确定性阈值（b）训练/微调价值项（c）逐步扩大支持集。Tianji 实机 rollout、Piper 的 136 条推理录制与 DAgger 是现有仅有的带结局数据来源。
5. 按既定规则，MuJoCo 只做最终策略验证，不作为评分器的结局来源（如需放宽由用户决定）。
6. 离线不可验证的部分写明：OOD 候选排序是否正确、是否存在模型被利用（predicted-success 但真实失败）。门槛只能证明示教分布内与合成 OOD 上的行为；OOD 成功路径的识别能力要靠第 4 条的试验数据来评估。

### 结论与建议

- 免训练时间池化不能解决小扰动分辨问题；短时域（h16 或更短）+ 整段目标的单调项 + 子目标的区分项组合更值得试，例如 S = S_G-A(h16) + λ·S_G-C(pool)，λ 只在 fit 内选。
