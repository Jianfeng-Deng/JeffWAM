# E34 设计任务（只设计，不写代码，不训练）

## 背景
- 项目：天机双臂 + Wuji 灵巧手，抓瓶子放入箱子；只用顶视相机；54维关节(A7+B7+L20+R20)；FK 手部几何可作输入。
- 当前最佳 E33-B（runs/e33_20261104/B/run/ep80.pt）：DINOv2-B 编码 → 12×20=240 个 256维共享潜变量 token；Transformer 预测器吃 z_t + 32步动作 token + FK 手 token，预测 +16/+32 帧的 z；flow-matching 动作头输出 32×54 chunk；损失含前景加权 JEPA、逆动力学 0.1、mask 头 0.5、重建 0.25；EMA 目标 + VICReg 方差项。代码见 tools/e33_model.py / e33_train.py / e33_eval.py，设计合同见 notes/2026-11-04-e33-contract.md。
- E33 评测：266 个留出窗口(9 条 episode)，相对"保持当前姿态"的步级误差百分比；mask IoU 对比"复制当前 mask"。B 的 mask 头只在右手上优于复制，瓶子(0.44 vs 0.67)、箱子、左手都不如复制。
- Astra 的评审(runs/report_20261103/ASTRA_ROOT_CAUSE.md，第 62、65、51 行附近)提出：对稠密潜变量预测的补充——"低维因子化状态动力学头"：预测瓶子位姿/速度、接触/抓持模式、与箱子关系；机器人运动由有序 FK 给出，静态箱子用恒等，只学物体残差；多步状态一致性(+5/+10/+20)；分别报告 teacher-forced 与 rollout 误差。

## 用户要求
- 这是独立实验 E34，不得混进 E33。低维状态头作为在 E33-B 之上的**附加头**（可以冻结 B 编码器，也可以联合微调，请你评估并推荐）。
- 动作预测与动力学是核心目标；不要丢掉稠密潜变量预测与重建。
- 约束：没有仿真/3D oracle 标注；只有顶视图、54维关节、各 episode 的 slot mask(0–5 瓶子相关,6 左手,7 右手,8 箱子)。GPU(H20-191)是共享的，总预算 ≤3 GPU 小时。严禁使用腕部相机、严禁读取他人受限目录以外的权限。

## 请你(sol, high)回答并给出可编码的设计
1. 低维物体状态从哪里来？只用现有数据，能否从 slot mask 得到 2D 质心/包围盒/面积/可见性，以及"抓持/在箱内"等离散标签？标签质量风险(遮挡、深色瓶子漏检)怎么控制？是否需要先做一个"标签可靠性"检查？
2. 头的结构：输入(z_t 池化/按 slot 的注意力池化 + FK 手 token + 动作序列)，输出(物体状态残差 +5/+10/+20 的对应帧数，离散模式)，损失，是否 flow-matching 还是确定性，参数量。
3. 与 E33-B 的关系：冻结 vs 联合训练；状态头的预测能否反馈进动作策略(作为额外条件)——给出一个最小可行的接入方式和一个纯诊断方式，建议先做哪个。
4. 评测：teacher-forced 与 rollout 分开；对比基线(复制当前状态/只用状态不用动作/动作换位 shuffled)；动作敏感性检验(同一起点换不同动作，预测应不同)；通过标准要预先写死，带 episode bootstrap CI。
5. 实现拆分(文件、接口、烟测项)，供 luna 编码；GPU 小时估算与磁盘估算。
6. 明确列出失败条件与"不做"的事。
