# E33 接口契约（Claude 制定，2026-11-04；所有子任务必须遵守）

E33 = 在 E32 无教师版基础上按用户 2026-11-04 的设计意见做的三组对比实验 B / C / D。**不含**低维状态头（那是 Astra 提出的组件，单独做 E34，不要混入）。不使用任何教师/OpenWAM。

## 沿用 E32（不要改）
DINOv2-B 初始化（与 E32 相同，最后 4 个 block + norm + proj 可训练）、顶视裁剪 rows 96–479→320×192（内部 336×560→24×40→池化 12×20，240 个 token）、无腕部相机；32 步 flow 动作头；FK 手部 token（tools/e28_hand_geometry.py）+ 动作 token 一并输入 Transformer 预测器；无物体槽、无门控；动作归一化 (command − measured_q − a_mean)/a_std；窗口索引与 split（data/e32_windows_20261103，9 个 E26a 留出 episode）；数据类 tools/e32_data.py 的 E32Data(no_teacher=True)；优化器与 E32 相同（lr 3e-4、ViT 2e-5、cosine、AdamW wd 1e-4、梯度裁剪 1.0）；batch 8 × accumulation 2；GPU 单卡、bf16/tf32 同 E32。代码复用 tools/e32_*.py、tools/e27a_balance_20261103.py（object_pixel_weights）、tools/e28_hand_geometry.py，**不得修改它们**，新代码写 tools/e33_*.py。

## 相对 E32 的改动（B 为基准）
1. **共享潜变量**：编码器输出单一 z∈R^256（每 token），不再拆 dyn/app，删除正交惩罚；预测器预测完整 z 在两个未来时刻（原始帧 t+16、t+32）的值；解码器、掩码头、flow 头都读 z（未来读预测的 z）。
2. **前景加权 JEPA**：JEPA 损失（cosine + 0.1×LayerNorm-L2，与 E32 相同）按 token 加权：w = 0.2 + 0.8·m；m∈[0,1] 为目标帧干净掩码（左手 slot6、右手 slot7、瓶子 slot0–5 并集、箱子 slot8，来自 data/object_masks_clean_20261102/masks_24x40_e26a.npy）并集在 12×20 网格上的平均池化后再按 [0,1] 截断；每个 batch 把 w 归一化到均值 1。rec 损失沿用 E27a A2 的 object_pixel_weights（权重 0.25）。
3. **逆动力学头**（权重 0.1）：输入 (z_t, z_target(t+16)) 的池化表示（实现自定，小 MLP），预测原始帧第 1–16 步的归一化动作均值（54D），MSE；z_target 为 stop-grad 目标编码器输出，梯度流入 z_t 的编码器。
4. **掩码头**（权重 0.5）：小卷积头从 z 预测 4 通道掩码（左手、右手、瓶子并集、箱子），在 12×20 上与对 24×40 掩码平均池化后的目标做 BCE+dice；监督三处：当前 z_t、预测的 z(t+16)、预测的 z(t+32)（目标为对应时刻的掩码）。
5. 其余损失：JEPA 1.0、flow 1.0、rec 0.25（读 z，当前 + 预测未来，同 E32 构造）；B/D 另有 VICReg 方差项 0.01；目标编码器 EMA 动量 0.996→1（余弦）。

## 三个变体（--variant）
- **B**：上述全部（EMA 目标 + 方差项）。
- **C**：同 B，但去掉 EMA 目标拷贝和方差项，改用 SIGReg 防坍缩：使用项目里 upstream LeWAM 的 `lewam.models.module.SIGReg`（路径/导入方式参考 tools/train_lewam_upstream_episode_split_20261031.py），SIGReg 的权重与超参读 upstream 的默认配置并在报告中写明；JEPA 目标取同一步在线编码器在未来帧上的输出（stop-grad，无 EMA）；SIGReg 作用于在线潜变量（当前帧与未来帧 token 的批量）。
- **D**：同 B，但 flow 头的 memory **不含**预测的未来 token（只含当前 z 与本体 token），预测器、JEPA、IDM、掩码头照常训练（仅作辅助，梯度仍进入编码器）。用于检验策略是否真的用到预测的未来。

## 训练与检查点
- --epochs 80（默认），每 10 个 epoch 保存 run/ep{N}.pt（仅 model 的 fp16 state_dict + config + stats + variant，不含优化器/EMA 目标）；run/latest.pt（完整可续跑，同 E32 机制）、metrics.jsonl（每步 losses 字典）、status.json、config.json（含 model_config、stats）。PAUSE 文件：runs/e33_20261104/PAUSE。
- 输出目录：runs/e33_20261104/{B,C,D}/run ；日志 train.log。

## 模型接口（e33_eval 依赖，必须提供）
`tools/e33_model.py`：
- `build_model(config, variant)`；`load_run(run_dir, ckpt='latest'|'ep40'..., device)` → `(model, stats, cfg)`。
- `model.eval_forward(image_uint8[B,3,192,320], q[B,54], act_norm[B,32,54], stats)` → dict：`pred_actions`（[B,32,54] 绝对关节指令，即 q + norm*std + mean，使用推理路径：10 步 Euler、无真实未来动作泄漏——预测器用 hold 动作）、`dec_cur`、`dec_f16`、`dec_f32`（[B,3,192,320]，f16/f32 用**真实动作**驱动的预测 z）、`mask_logits_cur/f16/f32`（[B,4,12,20]）。
- `model.infer(image, q, stats, steps=10)` → [B,32,54]（部署路径，不含解码器/掩码头/IDM）。

## 评测（T-E 实现）
tools/e33_eval.py 复用 tools/e32_eval.py 的 joints54_to_eef58/eval_action_chunks 和 tools/e32_eval_student.py 的逻辑（读后复用，不修改原文件），在 266 个留出窗口上输出与 E32 相同结构的 student_summary.json，再加掩码 IoU（手、瓶子、箱子；当前、+16、+32，分 moving/static 不要求），支持 --run、--ckpt、--out、--all-checkpoints（对 ep10..ep80 逐个评测并汇总成曲线 CSV）。tools/e33_compare.py：汇总 B/C/D 各 epoch 曲线 + E32 无教师 40 epoch（runs/e32_jepa_distill_20261103/t4/v2_noteacher_e40/eval/student_summary.json）+ hold 基线，输出 markdown 表和 CSV 到 runs/e33_20261104/report/。
