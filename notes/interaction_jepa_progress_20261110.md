# 交互状态端到端模型推进结果

日期为 2026-11-10，时区 America/Sao_Paulo。

## 实验范围与完成状态

本轮由我设定早期筛查预算。三个方案均使用训练 seed 47、相同参数初始化、相同官方 DINOv2 特征、相同窗口及动作采样条件，完成 8 个 epoch、512 次 batch=2 更新。三个训练作业均正常结束，后续只读诊断也已完成。

原 fit 内按既有 4701 划分使用 64 个训练 episode 和 16 个内部留出 episode。每集预选两个窗口，共 128 个训练窗口和 32 个留出窗口。训练归一化统计量仅使用 64 个训练 episode 的完整 2,159 个窗口。特征缓存为 CPU float16，模型计算为 float32。GPU 3 采用整卡 10% 的 PyTorch 显存分配上限。

两个 v2 方案分别通过世界/对象监督和纯动作监督训练公共状态。该对照同时改变监督来源与公共状态的梯度路线。v3 根据 v2 留出诊断改进对象状态监督，再进行同预算训练。

## 动作结果

|方案|最佳 epoch|前 8 步 RMSE rad|32 步 RMSE rad|
|---|---:|---:|---:|
|纯动作监督 actor_only|8|0.087444|0.204867|
|世界监督交互状态 v2|8|0.090310|0.214798|
|加强对象落地监督 v3|8|0.090548|0.215770|

v2 相对纯动作组，前 8 步增加 0.002866 rad，95% episode 区间为 [−0.000247, +0.005757]。32 步增加 0.009931 rad，区间为 [+0.005274, +0.014146]。

v3 相对纯动作组，前 8 步增加 0.003104 rad，区间为 [+0.000006, +0.005920]。32 步增加 0.010903 rad，区间为 [+0.006397, +0.014956]。前缀区间下界非常接近零，且所有区间均为未校正的逐指标区间。

分关节结果存在方向差异。v2 相对纯动作组，左手误差降低约 0.010626 rad，而 B 臂升高约 0.032713 rad、右手升高约 0.016372 rad。完整结果保存在 v2 的 SCREEN_RESULTS.json。

两组 v2 的动作 RMSE 均高于保持实测 q 的参照，v3 也仍高于该参照。q 保持参照在当前窗口上的前 8 步 RMSE 约为 0.066143 rad、32 步约为 0.185698 rad，用于检查开环动作拟合的实际增量。

## 对象状态监督发现与修订

首版使用普通像素 BCE，未充分处理瓶子前景稀疏性。v2 的 mask loss 虽降至较低水平，可见瓶 IoU 仍只有约 0.0121，预测前景面积约为标签面积的 5%。这表明原型的监督和读出尚未建立可靠对象状态。

v3 同时做了三项监督修订。

- 前景加权 BCE 加可见对象 Dice，并分别处理可见与空槽位。
- JEPA 按真实未来可见槽位计算，避免大量未知或空槽目标主导对象预测。
- 同一几何读出头接受纯视觉、历史融合状态、预测状态及真实未来 EMA 表征的监督，明确各分支的二维几何语义。

|诊断指标|v2|v3|
|---|---:|---:|
|当前可见瓶 IoU|0.01210|0.35510|
|当前瓶中心误差 px|33.78|34.04|
|预测前景面积比例|0.000244|0.016222|
|真实前景面积比例|0.004758|0.004758|

IoU 提高约 0.3430，配对 episode 区间为 [+0.2789, +0.4149]，16 个 episode 的点估计均改善。中心误差变化为 +0.266 px，区间为 [−1.339, +1.799]，尚未观察到中心定位改善。

三项修订共同实施，单项贡献仍待分离。mask loss 的定义已改变，跨版本损失数值不直接比较。

## 实例身份核查

v3 的预测前景面积达到标签的约 3.4 倍。进一步对有多个可见瓶的窗口检查槽位两两重合。

|诊断|槽位两两 IoU 均值|
|---|---:|
|v3 预测瓶掩码|0.64169|
|对应真实伪掩码|0.01223|

这说明不同预测槽位存在大量重复覆盖。0.355 的分割 IoU 改善具有类别前景识别成分，实例区分和几何状态仍存在缺口。该现象与中心误差保持在约 34 px 相容。

当前结构允许固定槽位 query 通过与当前 dense 特征的相似度输出掩码，几何头则单独从状态 token 回归中心。分割改善尚未转化为统一、可用于动力学和评分的实例状态。接下来需要把对象关联、空间提取与几何状态放在同一公共状态接口中验证。

## 事件标签映射

过滤规则保留经过复核的标签，排除用户 exclusions 和数值 confidence<0.8，缺失 confidence 保持缺失。共保留并映射 452 条事件，逐集核验 24 个 persistent-ID 档案，帧号与事件区间均通过范围检查。

其中 264 条标签的模型槽位不等于 PID−1。例如 episode 9 中 PID 2 对应槽位 0，PID 1 对应槽位 1。映射文件保留对象 PID、模型槽位、手、cycle、事件时间、区间、status 和原 confidence。

过滤后事件覆盖 13 个训练 episode 和 3 个留出 episode。当前事件仍主要是 G1/G2/G3/G5，分别对应接近、围拢、共动代理和箱上方投影。释放、稳定抓持、物理落箱及持续留箱监督仍有缺口。

此次训练沿用对象伪标签。事件映射作为后续关系监督清单单独保存，unknown 保留原义，事件时点尚未扩展成持续状态或失败标签。

## 后续架构工作

下一版应围绕实例状态接口推进。

1. 将观测对象表示为可匹配的集合，建立当前观测的实例分配，并通过因果关联维护局部身份。训练时按已核验身份对齐未来对象，避免每个未来单独重匹配而掩盖 ID 切换。
2. 将预测软掩码提取的局部特征、二维几何、可见性纳入对象状态，并检查分割与几何读出的一致性。以当前/过去观测预测产生这些输入，真实未来标签仅作为训练目标。
3. 保留机器人实测状态的明确通路，形成机器人状态、实例状态、交互关系与记忆的公共接口，再训练动作条件状态转移和后果评价。
4. 在相同内部协议下确认实例区分、静态保持和动作拟合，再评估增加窗口覆盖与训练预算。完整释放/结果评价需要相应标签与执行反馈。

当前数据尚未区分固定槽位语义、监督权重、表征能力与训练预算各自的贡献。上述结构工作以本轮发现为依据，性能需要后续验证。

## 限制与产物

每集只选两个窗口，128 个训练窗口约占全部可用训练窗口的 5.9%。所有方案的动作最佳点均在 8 轮预算上限，后期指标仍在改善，收敛情况待确认。只有一个训练 seed。内部留出集曾被历史实验检查，本轮又用于选 checkpoint，v3 还根据 v2 的留出诊断修订，所有结果均为探索性迭代。

对象身份与掩码来自跟踪伪标签。中心指标与原 E47 的瓶并集 IoU 使用不同口径。任务选择收益、反事实准确性和闭环成功仍待验证。

当前标签中心保持 oracle 的 all 分层包含当前不可见对象，中心在这些对象上无定义，汇总时已排除该项，仅保留双时刻可见的 moving/static oracle。原逐窗输出保留，汇总 JSON 记录了排除原因。

远端项目的主要产物如下。

- `runs/interaction_jepa_v2_screen_20261110/` 保存配对筛查、特征缓存、初始化、best/latest checkpoint、逐窗结果与 SCREEN_REPORT.md。
- `runs/interaction_jepa_v2_event_mapping_20261110/` 保存事件映射和来源哈希。
- `runs/interaction_jepa_v3_grounding_20261110/` 保存修订训练、COMBINED_REPORT.md、COMBINED_RESULTS.json、GROUNDING_DIAGNOSTICS.json 与 IDENTITY_DIAGNOSTICS.json。
- 各训练目录的 `source/` 保存运行时源码快照。随后为训练入口补上了已存在输出目录的保护，验证重复启动不会改写已有失败记录。

历史 checkpoint、初始试跑与当前实验产物均保留。研究入口位于 `research/interaction_jepa_v2/` 和 `research/interaction_jepa_v3/`，活动物体 planner 的后果模型按项目规定沿用 MuJoCo 路线。
