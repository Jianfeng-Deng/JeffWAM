先读 notes/2026-11-04-e38-design.md §2–§3（子目标事件 G1–G8、标注协议、数据格式、工作量），tools/e34_labels.py 与 runs/e34_20261104/audit（复用可靠 ID/valid/FK/mask 读取），tools/e28_hand_geometry.py、tools/e22_tianji_kinematics_20261101.py。

## 要做
1. 冻结 20 集 manifest（设计 §3：9 个历史 eval 按长度四分位各取 1 个作 test，其余 84 集按长度四分位各取 4 个共 16 集，每组 seed38 抽 1 dev + 3 fit，最终 12/4/4；并列按 episode ID；候选按 q 总变差/mask 漏检统计排序后 seed 抽取；列出替补顺序）；写入 data/e38_subgoals_20261104/v1/manifest.json 与 protocol.md（事件定义、阈值、unknown/not_observed 规则、JSONL schema）。不要看任何模型得分来选集。
2. 为每集生成联系图：每 8 原始帧一格，6×4 一张，保留帧号/秒数；两个版本：带叠加（瓶 ID 轮廓、左右手轮廓/FK 掌点、箱边界、FK 相对高度曲线）和无叠加原图；存 data/e38_subgoals_20261104/v1/sheets/{overlay,raw}/。事件粗区间展开用的 7–15 帧短序列联系图由一个函数按需生成（tools/e38_annotate.py --expand EP FRAME_A FRAME_B）。
3. 自动事件候选（G1–G8 的规则，设计 §2 表）：对 20 集输出 events_rule.csv（确认帧/最早最晚区间/unknown 原因/cycle_id），并统计各事件可判集数与 unknown 比例；FK 高度轴方向无法核对时 G4/G6 标 disabled 并说明。
4. 实测前 2 集的联系图张数、图像尺寸，估算 20 集双标所需视觉 token 与 Codex 时间，写入 qc.json。
5. CPU 烟测：episode 边界、0-based 与全局 row 对应、像素缩放（FK 640×384→320×192）、54 维顺序、读取 mask 的 valid、规则不读未来帧以外的信息之外的泄漏（事件规则只用到该帧及之前 3 帧作确认，另存最早可能帧区间）。
6. 不做标注、不启动 GPU、不改既有代码/data/runs；colleague-e、colleague-c 严格只读；无腕部相机。报告 data/e38_subgoals_20261104/v1/STEP1_REPORT.md（中文≤40行），追加 EXPERIMENT_LOG.md 与 worklog。
