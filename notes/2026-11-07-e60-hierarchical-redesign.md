# E60 分层结构重构思路（含编码器评估）

状态：**仅设计，未实现，未训练**。日期 2026-11-07。编号 E57–E59 已被 Piper 线占用，本笔记用 E60。

---

## 0. 为什么要重构

已有证据（详见架构整理文档）：

- E47 逐动作世界模型稳定优于旧结构，**手的预测好于 copy，但瓶子／箱子没赢过 copy**。
- 两轮诊断与 E54 说明：瓶子预测在 fit 上很好（运动瓶子 common IoU 约 0.72），在新 episode 上差（约 0.38），**落差约 0.34，是泛化问题**。改损失权重（W）和改参数化（D）都没救，val 在 ep10–ep40 就到顶。
- E55：免训练评分器只能剔除明显错误；**用真实未来做预言机也分不开小扰动**。
- 现状的根本错位：E47 用**同一套像素级目标**（24×40 掩码、RGB、960 个 token 的 JEPA 损失）覆盖 +4 到 +32 帧，权重 0.35/0.30/0.20/0.15。远处的未来本来就不确定，却被要求预测细节，这很容易变成背训练集。

已知数据事实：每个 episode 约 290 帧，15 Hz 下约 19.6 秒；划分 80/4/9；训练帧以 192×320 存储（`e47_data.py` 强制检查该形状）。

---

## 1. 设计原则

1. **越远越粗，越远越允许不确定。** 长程只预测轮廓、子任务、终局大概样子；即时层才预测细节。
2. **每层的目标、损失、评估、基线都不同**，不能再用一个指标衡量所有层。
3. **分层是隐式的、自上而下的条件**，上层预测作为下层的输入，不依赖候选打分。打分是可选的后续增强。
4. **全部目标自监督**：来自正向运动学（FK）、已有的 SAM 伪掩码、冻结的预训练特征、时间。不用 MuJoCo，不新增人工标签；人工事件标注只用于探针和评估。
5. **训练与推理的条件来源一致**（E36 hold-memory 失配的教训）：训练后期必须用上层的**预测**而不是真值作为下层条件。
6. **每层都有自己的笨基线**：copy（复制当前）、hold（不动）、时间先验（只按进度猜）。

## 2. 三层定义

| | L3 任务层（长程） | L2 子任务层（中程） | L1 即时层 |
|---|---|---|---|
| 时间尺度 | +64、+128 帧（约 4.3、8.5 秒）＋终局 | +16、+32 帧（约 1–2 秒） | 逐步 1–8 帧（约 0.07–0.5 秒） |
| 步长 | 32 帧 | 8 帧 | 1 帧 |
| 是否以候选动作为条件 | **否**：预测「按示教策略继续下去会到哪」，相当于子目标预测器 | 是：以 32 步动作块的宏动作嵌入为条件 | 是：逐步动作 |
| 预测目标 | ① 阶段码：在 fit 上对冻结预训练特征（池化到 3×5）＋低维 FK 做 k-means（K≈8），预测未来时刻的码；② 粗布局：手／瓶／箱在 6×10 网格上的位置分布；③ 终局粗布局：瓶子最终落在哪 | ① 末端位置与手掌朝向（FK，精确）；② 手—瓶相对向量与最小距离；③ 接触／抓持状态（掩码规则）；④ 瓶、箱质心与面积；⑤ 12×20 粗掩码 | 现有：24×40 掩码、RGB、token 级 JEPA、IDM、流头动作 |
| 损失形式 | **分布式**：阶段码交叉熵；粗布局热图交叉熵（允许多模态） | Huber（低维）＋BCE（接触）＋低权重 Dice/BCE（粗掩码） | 现有损失，权重向近端集中 |
| 防坍缩 | 目标固定（冻结特征上的聚类码、掩码），不会坍缩 | 目标固定（FK、掩码） | 保留 EMA 目标、方差正则、IDM |
| 评估 | 阶段码准确率、粗布局位置误差；**对照 copy 当前码和时间先验** | 末端误差（mm）、手—瓶距离误差、接触 F1、运动瓶子质心误差；对照 hold/copy | 现有 gates (a)–(e) 中 +4/+8 部分 |

要点：

- **L1 不再负责 +16/+32 的像素级预测**（或大幅降权），这部分改由 L2 用粗目标承担。这是本方案最直接针对「背训练集」的改动。
- **终局成功标签不能用**：93 条示教全部成功，「是否完成」恒为真。终局只预测**粗布局**（瓶子最后在箱子哪块区域），不预测成功与否。
- 「剩余进度 t/T」可以作 L3 的辅助目标，但 E38 已说明它本质是时间代理，**只作辅助，不作评估主指标**。

## 3. 层间接口

```
编码器 ──┬─ 全局池化 / 槽向量 ──► L3 预测器 ──► 阶段码分布 + 粗布局
        │                              │（作为条件 token）
        ├─ 物体中心读出(手ROI、按掩码池化) ─► L2 预测器(＋宏动作) ──► 中程状态
        │                                              │（作为条件 token）
        └─ 960 token ──────────────────────────► L1 预测器(＋逐步动作) ──► 细节
                                                      └──► 流头 memory ──► 动作块
```

- **读出分层**：L3 读全局池化；L2 读物体中心表示（E55 的 R1：手 ROI 4×4 ＋按掩码池化的瓶／箱）；L1 读全部 960 个 token。
- **条件方式**：上层的输出作为额外 token 加入下层预测器和流头的 memory。
- **训练时的条件来源**：前期用真值（未来帧编码出的上层目标），按计划逐步换成上层预测，训练后半段全部用预测。另加 10–20% 的条件随机丢弃，避免下层完全依赖上层。
- **梯度**：第一版对上层条件做 stop-gradient，让每层的损失保持干净、便于归因；端到端联合训练放到后续版本。
- **检验下层有没有用上层**：反事实交换测试，把两个窗口的上层预测互换，下层预测应当随之改变；若几乎不变，说明下层忽略了上层。

### 与现有组件的对应

| 组件 | 复用 | 新增 |
|---|---|---|
| 编码器、960 token | 复用 | — |
| L1 预测器、掩码／RGB 解码、IDM、流头 | 复用，调整地平线权重 | 接收 L2 条件 token |
| L2 | FK 几何（geo66）、掩码已有 | 小预测器（2 层）、宏动作编码、低维与粗掩码头 |
| L3 | 预训练特征缓存已有（E54 的 27281×960×768） | k-means 码本（只在 fit 上拟合）、小预测器、粗布局头 |

## 4. 分阶段实验（每阶段先写判据，过了才进下一阶段）

### P0 探针（不训练世界模型，约 0.5 GPUh，主要是特征提取）
用冻结特征（预训练 DINOv2-B 缓存，以及 E47 微调后的编码器输出）训练小探针：在 fit 上训练，在 val、test 上评估。

- L3：从当前帧预测 +64、+128 帧的阶段码与粗布局。
- L2：从当前帧＋动作块预测 +16、+32 帧的末端位置、手—瓶距离、接触。
- 健全性检查：k-means 码与时间进度的对应是否单调；若有 E38 试点事件，看码与事件是否对齐。

**进入 P1 的判据**：L3 在 test 上同时胜过「复制当前码」和「时间先验」（episode 级 bootstrap 区间下界 > 0）；且 L2/L3 的 fit–test 落差明显小于瓶子细掩码 IoU 的落差（0.34）。若不满足，说明连粗粒度的远程信号都学不到，先回到编码器问题（第 6 节）。

### P1 多尺度辅助头，不做条件（约 5 GPUh）
E47 加 L2、L3 头作为辅助损失，L1 的 +16/+32 细节损失降权。2 个臂（E47 基线、E47+分层头）× 2 个 seed，**训练 40 epoch**（E54 曲线显示 val 早期就到顶）。

问题：粗目标作为额外监督，能否缩小泛化落差、改善动作误差？

### P2 自上而下条件（约 6 GPUh）
三个臂：无条件 / **真值条件（oracle）** / 预测条件。
- 若 oracle 条件都改善不了 L1 和动作，就停止「条件式分层」，因为上限都不行。
- 若 oracle 有效而预测条件无效，瓶颈在上层预测质量，回到 P0/P1 改上层。

### P3 接入流头与可选打分
只有 P2 证明条件有效后再做。打分若要做，放在 L2/L3 的粗空间里，并且需要独立信号（人工事件标注）来验证，不能只靠示教。

## 5. 风险

| 风险 | 对策 |
|---|---|
| 数据少：每条约 20 秒，+128 帧覆盖 episode 的四成，阶段数很少 | 码本小（K≈8），L3 只做 2 个时刻；P0 先确认信号存在 |
| k-means 码学到的是外观而不是阶段 | 用低维 FK 一起聚类；P0 检查码与时间、事件的对应 |
| 下层忽略上层条件 | 条件随机丢弃＋反事实交换测试 |
| 训练／推理条件不一致（E36 重演） | 计划采样，后半段全部用预测条件 |
| 远程预测塌成平均 | 用分类和热图分布，不用 MSE |
| 粗目标定义选错导致「预测了个寂寞」 | 每层都对照 copy、hold、时间先验；赢不了就不进下一阶段 |

## 6. 编码器是否需要更换

### 6.1 现状（已在主机代码中核实）

- 主干：DINOv2-B/14 官方权重，**训练最后 4 个 block**，宽度 768，投影到 256。
- 输入链条：顶视裁剪 640×384 → **缩小到 320×192 存储** → 送入 DINO 前再**双线性放大到 336×560** → 24×40 个 patch。
- 数据加载强制要求帧为 192×320，说明训练帧只有低分辨率版本。

### 6.2 判断：先修三件事，再考虑换主干

按预期影响从大到小：

1. **分辨率链条有实际信息损失。** 原始裁剪 640×384 先缩成 320×192 再放大到 336×560，相当于 DINO 看到的是一半线性分辨率的图像再插值，**放大不会补回细节**。瓶子在 24×40 上约 17 个 patch，物体边缘和小位移受影响最大。直接把 640×384 缩到 336×560（只缩小约 0.875 倍），或者用 392×672（28×48 个 patch），能保留约两倍的线性细节。需要先确认原始视频还在，重新抽帧。
2. **微调还是冻结。** 用 80 个 episode 微调最后 4 个 block，很可能是 fit–test 落差的来源之一。DINO-WM 和 V-JEPA 2-AC 都冻结编码器。冻结还有一个好处：E54 已缓存全部帧的预训练特征，冻结编码器训练可以直接读缓存，不跑 ViT，训练会快很多。
3. **按层用不同编码器。** 分层后可以解耦：L3/L2 用**冻结的通用特征**（更好泛化），L1 用**高分辨率、可微调的特征**（保留细节）。这比整体换一个主干更有针对性。

### 6.3 候选主干

| 候选 | 是否在主机上 | 优点 | 顾虑 |
|---|---|---|---|
| DINOv2-B/14（现用） | 是 | 对照组 | — |
| V-JEPA 2-AC ViT-g | **是**（`models/vjepa2_ac`，11 GB） | 视频预训练，对运动敏感；同为 JEPA 体系；论文就用于机器人规划 | 约 10 亿参数，只能冻结并预先缓存特征；输入通常 256×256、patch 16，空间网格更粗；每 2 帧一个时间 tubelet |
| DINOv3 | 否 | 稠密特征与高分辨率稳定性更好 | 主机不能直连 Hugging Face，需沿用之前的本地解析下载方式；需核对许可 |
| SAM 2.1 Hiera-L 编码器 | 是 | 高分辨率、边界清晰，适合 L1 细节 | 偏分割特征，语义弱，不适合 L3 |

### 6.4 判断方法：探针对比，不训练世界模型

对每个候选（冻结）以及 E47 微调后的编码器，在 fit 上训练探针、在 test 上评估：

1. **细节**：当前帧瓶子 24×40 掩码 IoU。
2. **中程**：手—瓶距离、接触状态。
3. **粗粒度**：阶段码、时间进度。
4. **小运动灵敏度**：运动瓶子 patch 在相邻帧（t 到 t+1、t+2）的特征变化，相对静止 patch 噪声的信噪比。这直接对应 E55-2「预言机也分不开小扰动」。

每项同时报告 fit–test 落差。**换主干的判据**（评估前写定）：候选在 test 上 1 和 4 两项都显著优于 DINOv2-B，且 fit–test 落差不更大；否则保留 DINOv2-B，只做分辨率与冻结两项修正。

### 6.5 建议顺序

1. 分辨率修正 ＋ 冻结对照，和 P0 探针合并做（同一批特征）。
2. 候选主干的探针对比，先做主机上已有的 V-JEPA 2 和 SAM 2.1，DINOv3 等下载可行再加。
3. 是否换主干，等 P0 结果再定。
