# E65 独立评估：候选选择与标注粒度

文件标识：20261110。实际审阅日期：2026-11-09（America/Sao_Paulo）。

本次通过指定 SSH 读取项目代码、协议、报告、checkpoint 与数据；仅做 CPU 静态审计和数组统计，没有运行模型推理、训练、GPU 作业、仿真或操作他人进程。远端唯一写入是本报告新文件。报告中的实验建议均未执行。事实来源分为本次代码/数据核实、历史实验报告、分析假设；不把历史指标称作本次复现。

## 1. 结论

**E65 确认了候选池有模仿误差选择空间，且带真实未来参照的教师能利用其中一部分；没有确认可部署评分器能利用该空间。它不能证明“没有真实未来就不存在信息”，也不能证明“世界模型可以自行理解任务好坏”。**

“教师有信息，学生学不出来”可保留为预注册标签，但科学表述应为：**在本次特征压缩、模型族、训练预算和 episode 划分下，学生没有学到可泛化的选择优势。** 最可能是任务参照缺失、局部后果压缩和状态条件排序的学习困难共同作用；现有证据不能确定各自贡献。未发现足以解释失败的排序符号反转或直接未来标签泄漏。

标注确实不够支持精细接触与任务价值学习，但必须修正两个前提：

- “24×40 的瓶子平均只有 4 格”混淆了分辨率和统计口径；实际瓶子并集约 26.8 格，非空原始瓶槽约 13.4 格。
- 项目已有 E38/E49 事件代理及人工复核标签，不能说完全没有事件标注。缺的是完整、可信、覆盖足够且实际接入模型的接触/释放/结果监督，以及候选执行后果。

我延续上一份架构评估关于反事实覆盖不足、潜变量距离不等于任务价值的判断；修正“选择尚无收益证据”为“特权教师已有离线模仿排序收益，可部署选择仍未确认”。

## 2. 结果究竟说明什么

| 证据 | 支持的判断 | 不支持的外推 |
|---|---|---|
| K=16，随机 .1155、oracle .1011 rad，降幅 12.45%；seed48 13.22% | 候选差异足以容纳选择收益 | oracle 是示教关节 RMSE 上限，不是任务成功上限 |
| T1w 选择 Δ≈−.0047 rad，CI [−.006,−.003] | 真实未来匹配能取回约三分之一 RMSE 上限 | 未执行候选没有真实反事实视频，不能证明预测物理正确 |
| h4 rho .0026，h32 .2794；跨 seed T1w rho .2916 | 较长时距的预测变化具有可复现的示教排序信息 | 不证明信息来自瓶子；机器人姿态本身即可携带动作误差信息 |
| T2 rho≈−.009，选择略差 | 当前“到 episode 末帧潜变量更近”代理不可取 | 不排除阶段条件目标、事件价值或其他任务代价 |
| 动作距离四分位 T1 排序准确率 .551→.648 | 大差异更容易被教师辨别，完全不敏感的说法不成立 | 小差异弱可能来自噪声、目标或几何；不是单独分辨率因果证明 |

学生表的 14 个配置是 **dev** 结果，而不是 14 个独立 test 失败。最终只测试 dev 选中的 ridge/T1w/λ=1：准确率 .4874，CI [.464,.510]；选择 Δ≈+.0016 rad，CI 包含 0；上限占比 −11.4%，CI 约 [−25.5%,3.0%]。所以没有确认优势，也不能把低于 .5 的点估计解释成已确认反向排序。4 个 dev episode 选 14 个配置，9 个 eval episode 给区间，独立样本量仍很小；10,000 次 bootstrap 不会增加独立 episode 数。

T1 是特权监督：不但读取真实未来 EMA latent，还用**未来前景 mask**给 960 个 token 加权。学生不拥有这两种参照。这不是教师违规泄漏，而是教师与学生的信息条件不同。若两个相似当前观测对应不同意图/遮挡状态，教师可用未来区分，学生只能学习条件期望；但这尚未经过不可识别性实证检验，不能断言所有可预测信息为零。

## 3. 实现审计

审计对象为 `tools/e65_pipeline.py` 当前版本、备份 `tools/e65_pipeline.py.bak_before_split_fix`、冻结协议及 results JSON。

### 3.1 输入、目标、评估方向

`_score_bundle`（约465–510行）学生输入共37,009维：forecast四时距15×256、rollout同样15×256，共30,720维；当前池化latent 3,840维；相对q归一化动作的均值/标准差/末步162维；32×66候选geo共2,112维；q/dq/dq_valid/obs_fk共175维。没有拼入teacher分数、真实未来latent、真实动作误差、终帧目标或episode编号。真实动作只用于计算监督和评估。状态和FK来源是当前/历史观测，候选geo来自候选命令。

`_pairwise_dual_fit`（843行起）把目标更小者作为better，以softplus(−margin)鼓励其预测分数更大；MLP（874行起）使用同一方向；`_student_metrics`（827行起）以argmax选候选，并与−RMSE计算排序。**没有发现排序符号错误。** ridge实际是对偶L2正则pairwise logistic，不是平方损失ridge，但与协议中的数学定义一致。

标准化只在fit估计，dev只选型；eval没有用于学生超参数选择。A/B在eval上的预注册通过条件决定是否启动学生，这属于公开的门控依赖，不能说整个流程完全未看eval，但不是隐藏的特征泄漏。分片按row_index统一重排特征和标签，没有发现正常完整缓存下的错位。缺少某个features文件时加载器没有明确逐分片报错属于健壮性不足，不是本轮已发生错位的证据。

成对准确率始终对RMSE评估，包括以T1w训练的学生；因此它不能直接回答“学生是否学会了模仿教师排序”。代码建立了val_targets却未用它报告教师一致率。没有完整fit/dev的teacher排序准确率、fit选择收益及预测分差，限制了欠拟合/过拟合诊断。预测完全同分被记作错误而非0.5，应另报tie率；没有证据说明本轮低准确率由大量tie造成。

### 3.2 三处修复和协议一致性

diff确实只有三块：split episode计数、E47配置与统计加载、CUDA缓存转numpy。其中第二块额外调用fit_stats并覆盖model.stats，字面上违反“使用checkpoint统计、不重新拟合”的协议约束，不能仅称无语义影响的配置修复。

**本次已独立排除其数值影响：** CPU只读加载两个final.pt（map_location=cpu、mmap），以同一完整fit重新计算统计；mu_a、sigma_a、mu_q、sigma_q、mu_dq、sigma_dq对seed47/48 checkpoint和历史 `data_A/fit_stats.json` 的最大绝对差全部为0。未构建或运行模型。故这是应记录的执行偏差，不是本次学生失败的数值解释，也没有引入dev/eval统计。协议文字/判据没有在diff中修改。

结果JSON声称并列用准确率打破，但实际选型只比较严格更小的dev Δ；无证据表明出现完全并列，属于描述不一致。自动总体结论措辞也比协议的“未确认”保留规则更强；应以逐项门槛和区间解释。

### 3.3 更重要的结构性限制

1. **教师960 token、学生15 token。** 24×40→3×5每格平均64个原token。细小手瓶间隙、局部位移可能在平均中损失；教师使用未来前景定位加权，学生没有等价局部信息。当前结果并未检验“保留相同空间信息是否仍不可蒸馏”。
2. **线性排序抵消当前上下文。** 对s(c,a)=w_c·c+w_f·f(c,a)，同窗候选相减后w_c·c消失，当前latent/q等不能显式调节动作价值。预测本身仍依赖c，所以不是完全状态无关；但线性拼接无法表示当前状态与候选的额外交互。它是弱基线，不能代表一般条件价值函数。
3. **MLP参数多，但有效数据少。** 输入→256约947万首层权重，仅80个fit episode；2680个重叠窗×120对不是独立事件。无显式对象、关系、历史或阶段归纳偏置，原始向量高维拟合容易记住episode相关线索。
4. **目标把微小差别与大差别等权。** 所有非平局候选对都被当作同样可靠的严格排序；动作RMSE和教师分数非常接近时，实际任务可能等价。这会稀释有意义对的监督；本轮没有margin可靠性消融。
5. 标准化后统一除sqrt(37009)≈192.4，且clamp到±10，可能影响优化尺度与差异，但这是待查假设，不能据静态代码定性为bug。已有MLP训练末期loss为T1w .563–.669、RMSE .590–.671，低于随机log(2)=.693，表明优化至少学到部分训练信号；不能只称“优化器根本没学”。这些是epoch内训练loss，不是独立fit泛化评估。

## 4. 原因排序与设计决策

**较有依据：**教师与学生信息条件不同；局部空间大幅压缩；线性基线缺条件交互；MLP出现训练信号却没有dev收益；有效episode少；任务目标只定义了示教接近度。**合理但未确认：**遮挡/意图造成不可观测性，池化是首要瓶颈，时序历史不足，接触标签缺失导致价值学习失败。**未发现支持：**排序方向反了、未来标签直接进入学生、归一化重算改变本轮数值。不能排除未经逐项执行验证的其他实现问题。

目前可停止把下列路线当作已证实方案：直接部署当前T2终点距离；直接部署当前学生；仅加K就期待收益；把同一潜变量自评再端到端优化当作成功保证。不能排除所有规划、事件价值、局部读出或世界模型选择。

建议下轮按以下顺序设计新协议，不能在当前eval反复调参后继续称确认性验证：

1. 先报告fit/dev的教师一致率、RMSE一致率、score方差/tie率和按episode/阶段分层结果，区分教师蒸馏失败与teacher-to-RMSE失配。
2. 对照动作/状态only、后果only、两者结合；加入显式条件交互及当前/预测差分。若加入预测后果无增益，应停止将选择收益归功于世界模型。
3. 保持空间粒度或使用当前/过去观测定位的手、瓶、箱ROI；在同一信息预算上比较3×5与局部读出。不能用真实未来mask定位部署输入。既有缓存只有池化后果，原分辨率实验需要未来另行推理，本次未执行。
4. 优先做已有标签上的事件/关系读出与误差分层，再决定训练事件评分器；对接触、释放、留箱明确unknown。采用阶段条件且有外部锚定的代价，低置信度退回行为克隆。
5. 端到端联合优化放在独立留出集确认选择收益之后；必须有等预算纯模仿控制和冻结评分器控制。两个同数据同架构seed一致只能缓解单模型偶然性，不能替代真实候选执行验证。

## 5. 标注是否足够细致

### 5.1 掩码分辨率：足够粗定位，不足以定义接触和释放

E47确实把原始0–5瓶槽逐像素max，6/7手、8箱，组成四槽，见 `e47_config.py` 与 `e47_data.py::_slot_masks`。瓶实例身份、被哪只手抓、哪个cycle等关系没有保留在该监督接口中。

本次对完整只读数组 `(27281,9,24,40)` 计算：六瓶槽平均面积（含空槽）4.598格；只统计非空槽为13.406格；瓶并集为26.776格。历史 `diag_bottle_box/DIAG_REPORT.md` 的test未来h16/h32并集native面积26.71/26.43格，**common 12×20才是4.26/4.30格**。因此不能用“24×40每个可见瓶只有4格”作论证。固定六槽含大量空槽的平均数也不是典型可见瓶大小。

这不改变细粒度不足的判断：24×40每格对应192×320输入中的8×8像素（原裁剪图16×16像素）。小瓶轮廓、指尖间隙和遮挡边界会量化；瓶并集甚至不能直接回答哪一瓶移动。3×5池化再每格覆盖64×64输入像素，是更强的信息压缩。潜变量通道可编码亚格和全局上下文，故不能把格数当成绝对信息论上限；但掩码监督没有要求这些精细关系可读出。

二维mask相接不等于真实接触；手瓶共动不等于抓稳；瓶投影在箱内不等于落入并留在箱内。提高mask分辨率无法单独解决高度、遮挡、力或隐藏抓持状态。

### 5.2 已有事件标注：存在，覆盖和语义有限，而且E65未使用

本次直接统计 `data/e49_labels_20261105/final/labels_v1_partial.jsonl`：24个episode、608条，G1/G2/G3/G5各152条；394 observed、169 unknown、45 not_observed。source均记录human_review，其中607 reviewed、1 auto_agreed。这是文件记录的来源，未独立复核人的每条判断。

按 `exclusions_v1.json` 的episode/cycle/bottle/hand键剔除后剩492条：330 observed、122 unknown、40 not_observed。它们覆盖E47 fit 16集、dev 0集、eval 8集。**不能沿用E38自己的fit/dev名字直接加入E47训练；必须按E47 episode名单重映射。** observed不等于独立抓取次数，四事件和双手/多cycle会重复描述同一过程。

| 标注 | 实际语义 | 是否覆盖用户所问 |
|---|---|---|
| G1 | 接近 | 有代理/人工复核 |
| G2 | 手到位，人工看围拢 | 不是物理接触真值 |
| G3 | 手瓶共动的抓持代理 | 部分覆盖抓取/搬运，无抓稳保证 |
| G5 | 瓶投影运至箱上方 | 不等于真实入箱 |
| G4/G6 | 抬起/下放 | E38因高度轴未核验禁用 |
| G7/G8 | 释放/撤回 | E38保留unknown，E49不在标注范围 |

另有E38 `events_rule.csv`、clean masks的objects.json中近邻/共动target_grasp_binding，以及E60自动事件。这些均不能冒充独立接触真值；E60报告还记录接近距离Q25=0且使用严格小于，导致该事件无法触发，说明规则标签本身需要审计。发现的piper_events目录属于另一机器人事件来源，本次未证明其可迁移到天机，未计入上述覆盖。

所以“没有事件标签导致学生失败”应改为：**事件锚定未进入E65，已有标签对释放/结果不足，可能使任务价值难学；但不是已证明的E65失败原因。** E65有数值精细的RMSE和T1监督，缺少的是合适的语义与覆盖，不只是标签数量。即使补全示教事件，也没有给16条未执行候选各自真实结果，无法消除反事实缺口。

### 5.3 最小有价值补标方案

以下数量为可执行试点预算，不是保证成功的样本量估计。

- **先整理已有数据：**保留E49原文件，派生统一清单、排除原因和split映射；优先复核冲突ID/重复cycle。补标E47全部4个dev episode，使选型至少有对应事件标签；已有8个eval的标签只能用于冻结后的评估，不能训练。
- **首轮新增约12个完整episode：**4个dev，加8个尚未有标签的fit，按初始摆放、长度、左右手、可见性分层选取，不按模型分数选。先2集校准定义，再完成余下10集；若关键事件仍缺或一致性不足，先修协议而非立刻扩大全量。
- **对象与关系：**保留瓶ID、手、cycle/换手/重复尝试；标接近、可见接触候选、稳定共动、运送、可见分离/释放候选、投影入箱、撤手后瓶仍可见且留箱投影。可见代理与物理状态分栏；“抓稳/入箱成功”不可见时明确unknown。
- **时间粒度：**非关键段每4–8帧巡检；每个事件前后约0.5–1秒逐帧看15Hz视频。记录最早/最晚可能帧、确认帧、可见性和证据帧；允许±2–3帧不确定区间，不硬造唯一帧。窗口跨事件时用区间/关系标签，而非一张全局phase强行覆盖两只手。
- **空间粒度：**首轮约300–500张分层关键帧，人工核验目标瓶与交互手的实例mask/轮廓或中心、接触邻域、遮挡和箱边界。尽可能在原始可用分辨率标，保存原坐标后再生成低网格；无需一开始重标27,281帧。前后稳定帧、非接触近邻、遮挡和失败/重试都纳入。
- **质量控制：**标注者不看候选分数、预测图或“应有顺序”；先raw后辅助overlay；至少20%按episode/事件分层双标，所有接触/释放分歧人工裁决。报告有效覆盖、unknown率、事件presence一致性、时间区间重合、ID切换和边界误差。unknown不当负例，not_observed不等于动作失败；保留异常，不为整齐成功序列删掉难例。

先检查这些标签能否从真实当前/未来图像读出，再检查预测后果能否读出，最后检验候选排序的增量。若目标是真实动作好坏，还需以后获得同类状态下的成功/失败或轻微不同动作结果；本轮补标不能替代新增交互数据。

### 5.4 噪声、闪烁、遮挡影响多大

历史诊断在test邻帧瓶并集IoU均值 .9346、中位 .9744，极低IoU约 .295%、空标注帧2.31%；箱均值 .9763、无空帧。它支持**大规模随机闪烁不像全局主因**，却不能证明掩码语义正确：时间平滑的错误标签也会高一致，瓶并集会隐藏实例ID切换。

历史当前帧native瓶IoU .818，未来瓶线性读出低于当前，静止/运动层和fit/test都存在差异，支持“并非完全不可读，预测/泛化另有损失”。这些指标相对于伪标签而非独立人工真值，不能据此给伪掩码真实准确率。

E49排除表记录了ID分裂、重复cycle、跨cycle事件和手/瓶混淆；Pass B报告明确提到遮挡与tracker ID变化。这些是质量问题的具体证据，尤其会伤害小物体接触、释放等少量关键帧。瓶子消失可能是真遮挡，也可能漏标，不能统一标成已释放/已入箱。历史需复核点包括ep18约179/197、ep56约329、ep64约74/89帧。
