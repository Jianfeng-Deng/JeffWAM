# 任务 E33_sub v2 追加：像素重建损失（luna-max）

用户要求：E33_sub 中提高图像重建（rec）权重。现状：E33_sub v2 的 G 只在 token 空间训练（全240×256残差流 + 关节），**没有像素重建项**（E33 基座里 rec=0.25，L1+0.5×4×4池化L1，权重图 object_pixel_weights：瓶/手/箱=1、其余.05，每区域按面积归一）。

## 改动（只改 tools/e33sub_*.py，先备份到 runs/e33sub_full_20261104/v2a_backup/）
1. 在 e33sub_train 的 compute_losses 中加入 `rec` 项：把 G 的生成结果（R1：训练时由真目标加噪插值得到的 x̂_0 预测；R2：直接回归输出）解码为 ẑ_h = z_t + decode(v̂_h)，经**冻结的 E33-B 解码器**（model.decoder，保持 eval/冻结、不更新）得到图像，与真实 +16/+32（及 b=8 的 +8/+16 对应帧）图像计算与 E33 完全相同的 `FF.image_loss(pred, real/255, object_pixel_weights(mask,192,320))`。梯度只回传到 G（不进冻结 F/decoder）。
   - 真实图像与 mask 的取帧要与数据窗口的 h 对齐（b=16 对 +16/+32，b=8 对 +8/+16）；若 e33sub_data 当前不返回未来图像与 slot mask，则新增只读返回（memmap mode=r），不要改缓存数组。
   - R1 注意：只在 τ 使 x̂_0 有意义时计算（用 x̂_0=x_τ−τ·v̂ 的标准形式，按你实现的插值约定推导），并对 rec 用与主损失相同的 τ 采样，避免额外前向；如显存/时间过大可只对 batch 内一半样本计算，写明。
2. 新增参数 `--rec-weight`（默认 **1.0**，约为 E33 的 4 倍；0 时关闭，必须与现有 v2 结果数值一致作为回归测试）。总损失 = 原 v2 损失 + rec_weight × rec，其余权重不变。该修改记为“用户 2026-11-04 要求的预注册修订 A1”，写入 manifest 与 checkpoint 配置，旧 v2 无 rec 的 checkpoint 拒绝与新配置混用。
3. 评测：e33sub_eval 的解码指标（PSNR/物体 MSE/IoU）保持不变，另在报告中增加“rec-weight=0 与 1.0 在同一冻结 B 解码器下的对比表头”以便将来比较。
4. 验证：CPU smoke ①–⑫ 全部重跑通过；新增检查：rec 梯度只到 G、冻结 F/decoder 梯度为 None、rec-weight=0 时与旧损失逐位一致、b=8/b=16 帧对齐哨兵、R1/R2 各 20 步 smoke 的 rec 有限且下降趋势；参数量不变（7,672,364）。
