# 统一 SigLIP2 与动作潜变量对齐实验方案

本轮比较统一视觉语言编码后的直接动作学习，以及增加动作潜变量对齐后的动作学习。核心假设是，显式行为表征监督能提高语言条件的动作收益。两臂共享结构、初始化、冻结日程、策略更新数和数据流，使主要差异集中在对齐目标。以下数值为下一轮的预注册建议，当前状态为待实施方案。

## 对照与解释范围

|设置|S 直接 flow|A 动作对齐|
|---|---|---|
|视觉和文本|同一 SigLIP2 检查点的双塔|相同|
|视觉语言融合、条件注入和 flow|相同|相同|
|策略前 1350 步|冻结双塔，训练融合模块、flow 和子任务头|冻结双塔，训练同样模块，加入动作潜变量对齐|
|策略后 4050 步|部分解冻双塔并联合微调|相同，同时逐步降低对齐权重|
|机器人动作编码器|用于事后诊断|作为冻结的训练目标编码器|
|动作损失|flow matching|flow matching 加条件与行为对齐|
|策略更新数与有效 batch|5400，16|5400，16|
|初轮种子|6601|6601|

S 也采用冻结预热，是为了控制训练日程。如果让 S 从第一步全部解冻、A 分阶段训练，两臂差异会同时包含对齐损失与冻结策略，结果难以归因。本轮比较显式对齐带来的增量。动作编码器的预训练属于 A 的额外训练成本，单独记账，不能声称两臂总计算量完全相等。

E66 N64_A_BC 和 E68 C 是历史参照。视觉编码器、图像输入尺寸和融合结构发生变化，历史比较用于衡量新系统整体效果。S 与 A 才是本轮受控比较。

## 数据与条件契约

- 使用 E66 N64_A_BC 的原始 64 集、2159 个训练窗口、seed 6601，以及该子集的训练统计。79 个已标注 fit episode 的整体划分仍保留，本轮使用其中属于 N64 的部分。ep24 缺标注，条件为 NULL。
- dev 为 0、1、2、3，冻结回归集为 7、18、38、56、64、66、77、88、90。冻结集继续使用记录动作评价，语言由因果子任务头预测。
- 仅使用原有顶视图像。动作顺序保持 A7、B7、左手20、右手20，单位 rad。动作目标仍为 action[t:t+32]，锚定当前实测 q[t]。
- 训练条件统一为由 skill、object_category、hand 生成的受控英文模板，与部署预测的模板完全一致。保留 idle、retreat 的真实语义，NULL 单独表示缺失或未知。
- unknown_flag=true 对应 NULL。result、结束帧、下一段命令和未来图像均不进入策略条件。
- L0 固定为 Put the bottles and cups into the box.，两臂相同。
- 两臂均使用每样本 0.2 概率双手 NULL、另 0.1 概率单手 NULL 的互斥 dropout，记录实际比例。
- 对齐损失只用于两手条件已知、且本次没有语言 dropout 的训练样本。NULL 或 dropout 样本仍参与完整 flow 和子任务头训练。idle/retreat 的 object_category=NULL 是合法无对象标签，不作为未知语言排除。
- 原始 label_en 仅用于 dev 的措辞变化诊断。模型生成标签用于训练条件及弱监督，不作为测试真值或选型依据。

## 共享模型结构

### 成对视觉语言编码

使用已下载的 google/siglip2-base-patch16-224，同一 revision 的视觉塔与文本塔。当前固定版本为 75de2d55ec2d0b4efc50b3e9ad70dba96a7b2fa2，许可证 Apache-2.0，复用已记录的权重 SHA256。

该检查点的 config.model_type 为 siglip。实现应使用 AutoModel/AutoConfig 选择实际类，按固定分辨率模型处理，避免把 NaFlex Siglip2VisionModel 的 patchified 输入接口直接套到此检查点。

整幅原有 192×320 顶视图像缩放至模型原生 224×224，采用该版本官方图像处理配置并记录配置哈希，保留完整视野。两臂使用相同预处理。视觉 patch16 输出 14×14 个局部 token，保留其空间结构，并保留模型原生池化视觉向量。文本使用同一模型的原生池化向量，最大长度沿用 64。

预训练的共享语义关系主要由池化图文表示建立。局部 patch 与指令目标的对应仍由后续融合模块及机器人监督学习。

### 视觉语言融合

1. 视觉局部特征和原生池化向量分别投影至 d=256，组成 197 个视觉 token。
2. 左右手模板文本分别投影至 d=256，加手 ID 嵌入。
3. 使用两个 pre-LN cross-attention block，让两个手别查询读取当前视觉 token。每层 8 heads，FFN 宽度 1024，保留查询残差。
4. 拼接两手输出，经两层 MLP 生成 c[t]∈R^256。c 的输入仅包含当前图像和两手条件。
5. 当前 q、因果 dq 和观测 FK 沿用 E47 状态分支，直接进入动作生成器。子任务头另外读取最近 8 帧 q。

### 动作生成器

保留 E66 的 32×54 flow matching、3 个动作 Transformer block、10 步 Euler 和当前 q 锚定输出。视觉/状态 cross-attention 使用 197 个视觉 token 加 3 个状态 token。

每个动作 block 通过独立的条件 MLP，从 c 产生 gamma 和 beta，调制该 block 的 FFN 输入。

    h_cond = (1 + gamma(c)) * LayerNorm(h) + beta(c)

条件 MLP 输出层采用小幅非零初始化，例如 Xavier gain 0.01、bias 0，确保初始行为稳定且条件分支从第一步有梯度。两臂初始化完全一致。

对齐损失直接约束这个实际进入 flow 的 c。对齐分支共用该表示，避免只训练一个动作生成器从未读取的旁路投影。视觉/状态仍可影响动作，是否真正使用 c 通过条件干预评价。

### 子任务头

两臂均保留 E68 的因果子任务头。输入为 detach 后的当前视觉特征以及最近 8 帧 q，输出左右手 skill 的 11 类 logits 和 object_category 的 3 类 logits。损失权重 0.1，独立裁剪梯度，梯度只更新子任务头。

部署时取 argmax，再生成与训练完全一致的模板。该结构支持阶段和对象类别条件；颜色、瓶盖等对象身份信息未包含在这个接口中。

## 动作潜变量

训练目标为前 8 步归一化动作残差 a[t,0:8]∈R^(8×54)，使用 E66 的 N64 训练统计。前 8 步与主评价时域一致，可减少长动作块跨子任务阶段造成的语义混合。

动作编码器 E_a 由 54→256 的输入投影、8 个时间位置嵌入、2 层 Transformer 和一个池化查询组成，输出 u∈R^256。重建器 D_a 为 256→512→432 的 MLP，输出前 8 步动作残差。

E_a 的输入只含动作残差。原始关节姿态、episode ID、时间戳和语言标签不进入动作编码器，以减少利用共享标识或静态姿态完成检索的机会。

预训练重建损失采用四个物理组等权的归一化 MSE。

    L_rec = mean_over_4_groups(mean_over_8_steps_and_group_joints((D_a(E_a(a)) - a)^2))

固定训练 1000 更新，batch64，AdamW lr=3e-4，weight_decay=1e-4，cosine 衰减，seed6601。仅使用同一 N64 fit 的动作窗口。训练后冻结 E_a 和 D_a，并缓存所有 fit 窗口的 u。

记录 fit/dev 重建误差、潜变量方差，以及相对训练均值预测器的重建改善。若重建无改善或潜变量塌缩，需要先诊断目标编码器，不能把后续失败直接解释为对齐目标无效。dev 重建指标只用于诊断，不据此反复调整编码器或选择策略检查点。

完整 32 步动作仍由 flow loss 训练。前 8 步动作潜变量仅提供额外的近期行为监督。

## 对齐损失与正负样本

距离均按 A7、B7、L20、R20 四组等权计算。记 a 已采用固定训练统计归一化。

    d_q(i,j) = mean_over_groups(RMS((q_i - q_j) / sigma_q))
    d_a(i,j) = mean_over_groups(RMS(a_i[0:8] - a_j[0:8]))

### 正样本

每个有效 anchor 的唯一必有正样本为同 episode、同原始帧 t 的配对动作潜变量。策略侧使用当前图像和当前两手模板，目标侧使用对应记录动作的前 8 步。

可增加多正样本，但必须同时满足以下条件。

- 两手的有效技能、对象类别模板一致。
- 当前实测 q 的组归一化距离不高于 q_pos。
- 前 8 步动作残差的组归一化距离不高于 a_pos。

q_pos 和 a_pos 分别取固定 50000 对跨 episode fit 样本距离的第 5 百分位数，采样 seed6601。阈值由训练数据一次生成后锁定，保存样本键与哈希。仅技能相同不充分，因为不同物体位置可能需要相反的动作。

### 负样本和排除项

从冻结的 fit 动作潜变量库中选取最多 64 个候选负样本。

- 最多 32 个按 episode 均衡随机采样。
- 最多 32 个从状态距离较近、两手模板不同的训练窗口中选取，作为较难的非配对样本。
- 所有候选的前 8 步动作距离必须至少达到 a_neg。a_neg 为上述训练样本对动作距离的中位数。
- 排除同 episode 帧间距小于 32 的窗口，以及已进入正样本集合的窗口。
- 排除缺标注、unknown 和动作相近但语义不同的含糊候选。
- 候选不足时使用实际数量；没有可用负样本时跳过该 anchor 的对齐项，保留 flow loss。记录覆盖率及负样本数量分布。

这些负样本表示非配对的示教行为，不能被解释成已验证的物理错误或失败动作。跨场景动作仍可能有多解，对比损失只作为辅助项。

### 损失定义

对 c 和冻结的 u 分别做 L2 归一化，固定温度 tau=0.07。相似度、归一化及 log-sum-exp 用 FP32 计算。对每个 anchor 使用多正样本对比损失。

    score(i,j) = normalized(c_i) dot stop_gradient(normalized(u_j)) / tau

    L_align(i) =
        -log(sum_{j in P_i} exp(score(i,j))
             / sum_{j in P_i union N_i} exp(score(i,j)))

对齐只向视觉语言融合、条件表示以及在相应阶段解冻的视觉/文本参数传播梯度。冻结动作编码器不接收对齐梯度。该损失不把不同物理动作强制归入同一技能中心。

对比损失仍可能主要利用视觉信息。为观察语言贡献，检索诊断同时报告原始模板、NULL 和同 episode 打乱条件下的结果，并单独报告较难候选集合的表现。

### 总目标

S 的目标为：

    L_S = L_flow + 0.1 * L_subtask + lambda_anchor * L_anchor

A 的目标为：

    L_A = L_flow + lambda_align * L_align
          + 0.1 * L_subtask + lambda_anchor * L_anchor

L_flow 保留 sigmoid-normal tau、高斯噪声，以及前8/中8/后16步的 4/2/1 权重。策略与辅助子任务头分别裁剪梯度至 1。

L_anchor 用于联合微调阶段维持预训练图文表示，比较当前双塔的原生池化向量与初始冻结模型的同输入池化向量。

    L_anchor = mean(||normalize(v)-normalize(v_initial)||^2
                    + mean_over_hands(||normalize(l)-normalize(l_initial)||^2))

NULL 文本不参与文本 anchor 项。初始向量可缓存，缓存生成仅依赖对应图像和合法文本。两臂的 anchor 项和权重相同，固定 lambda_anchor=0.1；冻结阶段该项为零。

## 训练阶段与配方

|阶段|更新数|S|A|
|---|---:|---|---|
|行为编码预训练|1000|共享诊断编码器，策略不读取其输出|获得冻结行为目标编码器|
|冻结双塔预热|1–1350|L_flow 加辅助 CE|L_flow 加 0.05 L_align 加辅助 CE|
|部分解冻联合训练|1351–2700|L_flow、辅助 CE、0.1 L_anchor|同 S，加对齐项，权重从 0.05 线性降至 0.01|
|稳定联合训练|2701–5400|同上|同上，对齐权重固定 0.01|

“先对齐”在这里指先稳定视觉语言双塔、建立条件到行为的映射，再解冻联合适配。冻结预热阶段同时训练 flow，使行为表示始终服务于实际动作生成。

联合阶段，两臂均解冻视觉塔末 2 个 block、文本塔末 2 个 block，以及各塔末端 norm/原生输出投影；其余双塔参数冻结。视觉基础 lr=2e-6，文本 lr=1e-6，融合、条件调制、flow 和子任务头 lr=3e-4，AdamW weight_decay=1e-4。策略使用覆盖 5400 步的同一 cosine 日程。冻结期间编码器参数组 lr=0，解冻后进入当前日程对应的 lr。

文本塔解冻后，训练必须真实前向计算文本，不能继续读取初始冻结文本缓存作为当前特征。缓存仅供冻结阶段及初始 anchor 教师使用。

有效 batch16，优先 microbatch4×4 梯度累积，bf16。两个策略臂共享每步窗口顺序、flow 噪声和 tau、语言 dropout 随机流。正负样本采样使用独立随机流，避免推进 flow RNG。

固定最终 step5400 作为比较检查点。1350 和 2700 保存训练曲线及机制诊断，不用弱标签准确率或检索准确率选择策略。

## 评估协议

### 主动作评价

沿用 E66 原评估实现和固定噪声。冻结 9 集各 4 窗口，共 36 个窗口；dev 4 集各 4 窗口，共 16 个窗口。每个窗口 4 个固定噪声种子各采样一次，10 步 Euler，再平均动作块。

主指标为前 8 步四组等权的归一化 RMSE。另报 32 步 rad RMSE、A7/B7/L20/R20 分组误差、左右手误差、左右腕 FK 位置和旋转误差、速度/加速度 RMS、关节限位违反比例。归一化分母固定使用 E66 common_eval_stats。

冻结 9 集的主模式为子任务头因果预测模板。dev 单独报告：

1. 子任务头预测模板。
2. 给定正确类别的同构模板。
3. 全 NULL。
4. 同 episode 中更换为不同片段的模板。
5. 保持已标注语义、使用原始 label_en，作为措辞与对象细节变化诊断。

episode 等权汇总，沿用 E66 的 10000 次配对 bootstrap 和 seed4704。主要比较 A 对 S，历史参照另表给出。冻结集用于最终预注册比较，所有开发与代码修改依赖 fit/dev。

### 条件利用和对齐诊断

- 同状态、同噪声的模板/NULL/打乱条件动作差，报告前 8 步和 32 步的 rad RMS、归一化 RMS，以及原动作误差变化。
- 单独报告包含 approach、grasp、lift、transport、place、release 等活动阶段的 dev 窗口，避免 idle/retreat 占比掩盖条件效应。
- 对齐检索在 dev 内构建固定候选集，同时报告随机候选与状态相近候选的 Recall@1、Recall@5、正负相似度差。每个候选集报告实际大小。语言打乱后检索是否变化也要记录。
- 动作编码器重建误差与潜变量方差。
- 条件向量、调制参数的数值分布，以及动作损失/对齐损失对融合层与双塔的梯度范数。
- 子任务头 skill/object 准确率仅作弱标签诊断。
- 单步推理延迟 p50/p95，包含图像、子任务头、文本条件和一次完整 10 步 flow 采样。阶段内按模板缓存的优化结果单列。
- 正式主表覆盖范围保持一致。全部 dev 可用窗口的额外分析只用于机制诊断，报告独立标识。

### 判据

- A 在冻结 9 集部署主指标上比 S 降低至少 5%，且 episode 配对相对变化的 95% CI 全部小于 0，判为“显式动作对齐带来动作收益”。
- 仅给定模板模式改善、部署模式不改善，说明收益受因果子任务预测限制。
- 检索改善但动作指标未达到判据，记录“表征对齐改善，动作收益未证实”。
- 打乱条件后误差变化绝对值低于 1%，按 E68 标准标记“条件利用弱”，同时保留实际预测动作差。误差变化小不等于输出完全相同。
- 该数据集的 L0 恒定，结果主要支持阶段/对象条件是否有效。对任意操作者意图及同场景反事实指令的泛化，需要对应的真实指令与动作证据。

## 冒烟、预算与恢复

- 初轮单种子6601，建议上限 8 GPUh，包含动作编码预训练、两臂冒烟、训练、评估和诊断。该预算是下一轮的提议，与 E68 已用预算分开记录。
- 实施前以实际单步耗时估算完整成本，锁定两臂相同配置。可先缩减重复诊断计算。若预算不足以完成两臂同等更新数，明确报告截断，不能用不等训练量判胜。
- 真实冒烟覆盖编码器加载及预处理、动作编码器 20 步、两个策略臂各 20 步、冻结到解冻切换、每种 dev 条件评估，以及报告生成。
- 验证双塔冻结阶段梯度为零，解冻范围正确；A 的动作编码器始终冻结；辅助头梯度隔离；对齐所用 c 与进入 flow 的 c 是同一表示；正式推理输入不包含真实动作潜变量。
- 采用服务器 setsid/nohup 驱动、latest.pt 续跑、逐阶段完成标记、status.json、失败记录和持久 GPU 预算。最多并用 3 张空闲显存至少 24 GiB 的卡。
- 新实现使用独立实验目录和 tools/eXX_*.py，实验编号在实施时检查占用情况后确定。保留 E47/E66/E68 原始比较结果。
- 只有首轮达到动作判据后，再考虑 seed6602 的重复验证，预算另行明确。

## 研究依据

成对双塔提供预训练图文语义基础，见 [SigLIP2](https://arxiv.org/abs/2502.14786)。利用条件与行为做对比模仿已有 [CLIP-RT](https://clip-rt.github.io/) 的研究先例。本文所提的连续 54D 动作编码、冻结日程、候选构造和损失权重是针对当前项目的实验设计，需要由本轮结果验证。
